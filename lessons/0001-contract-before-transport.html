Contract before transport

Learn where TypeScript's promise ends, then place ArkType validators at the two boundaries that matter.

5 minutes One idea One retrieval check

The goal

By the end, you should be able to explain why an SDK needs runtime validation even when every project involved uses TypeScript.

Core fact

TypeScript erases types when it emits JavaScript. A type annotation can guide the compiler, but it cannot inspect a request or response while the program runs.

This is why response.json() as QuizResponse is a promise made by the programmer, not proof about the server's JSON.

Protect both sides of the network

SDK input unknown caller data
→
HTTP JSON untrusted transport
→
SDK output validated questions

Our contract package will export ArkType schema values. The server and SDK will import those same values, so each boundary gets runtime checks and each codebase gets inferred static types.

The first contract

import { type } from "arktype"

export const GetQuestionsInput = type({
  category: "string",
  count: "1 <= number.integer <= 50",
  "difficulty?": "'easy' | 'medium' | 'hard'"
})

export type GetQuestionsInput =
  typeof GetQuestionsInput.infer

GetQuestionsInput exists in both worlds. The value runs in JavaScript and validates data. typeof GetQuestionsInput.infer exists only during type checking.

const result = GetQuestionsInput(maybeInput)

if (result instanceof type.errors) {
  throw new Error(result.summary)
}

// result is now validated and precisely typed
