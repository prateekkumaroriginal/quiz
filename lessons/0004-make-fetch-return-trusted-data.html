One method, two gates

The method signature catches mistakes in TypeScript source. Runtime input validation also protects JavaScript users and callers that use unsafe assertions. Response validation protects every caller because the network can return anything.

Validate around fetch

async getQuestions(input) {
  const validInput = GetQuestionsInput(input)

  if (validInput instanceof type.errors) {
    throw new QuizClientError("INVALID_INPUT", validInput.summary)
  }

  const response = await fetchImpl(`${baseUrl}/v1/questions`, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify(validInput),
  })

  const body: unknown = await response.json()

  if (!response.ok) {
    const apiError = ApiError(body)
    // Convert the validated API error into an SDK error
  }

  const output = GetQuestionsOutput(body)

  if (output instanceof type.errors) {
    throw new QuizClientError("INVALID_RESPONSE", output.summary)
  }

  return output.questions
}

Response.json() parses the body but can produce any JSON-representable value. Assigning it to unknown prevents that uncertainty from leaking past the SDK.

Name failures by responsibility

INVALID_INPUT

The caller supplied options outside the contract. The SDK does not send a request.

API_ERROR

The server returned a non-success HTTP status. When possible, the SDK validates and preserves the shared API error message.

INVALID_RESPONSE

The server claimed success, but its body violated GetQuestionsOutput. This is a broken API contract, not a valid empty result.

Inject fetch to test the boundary

The client accepts a fetch-compatible function. Tests can supply a fake response without making a real network request.

it("rejects a successful response with the wrong shape", async () => {
  const fetchMock = vi.fn<typeof fetch>(async () =>
    jsonResponse({ banana: true }),
  )
  const client = createQuizClient({
    baseUrl: "https://quiz.example.com",
    fetch: fetchMock,
  })

  await expect(
    client.getQuestions({ category: "science", count: 1 }),
  ).rejects.toMatchObject({ code: "INVALID_RESPONSE" })
})

Primary sources

MDN's Response.json() reference states that parsing may produce any JSON-representable JavaScript value. MDN's Response.ok reference defines success as an HTTP status from 200 through 299. ArkType's traversal API documents direct schema invocation and type.errors.

Q&A

  1. If TypeScript already checks the argument to getQuestions(), why validate it again at runtime?

    Show answer

    Published packages can be called from JavaScript, and TypeScript callers can bypass checks with assertions or any. Runtime validation stops bad input before the request.

  2. The server returns HTTP 200 with { "banana": true }. Which error should the SDK throw, and why?

    Show answer

    INVALID_RESPONSE. The HTTP request succeeded, but GetQuestionsOutput rejected the response shape. Returning it would break the SDK's promise to return validated questions.
