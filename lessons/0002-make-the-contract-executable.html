@quiz/contracts is deliberately separate. The future server and SDK will depend on this package instead of copying its schemas.

Design rule

Code that owns an API contract should not belong exclusively to either side of that contract.

One value, two jobs

export const GetQuestionsInput = type({
  category: Category,
  count: "1 <= number.integer <= 50",
  "difficulty?": Difficulty
})

export type GetQuestionsInput =
  typeof GetQuestionsInput.infer
  • The exported value validates data while JavaScript runs.
  • The exported type checks callers while TypeScript compiles.
  • The numeric range is stricter than TypeScript's plain number.

Turn the claim into proof

The most important test begins with valid JSON that has the wrong fields. Its type is explicitly unknown, preventing us from using it before validation.

it("rejects valid JSON with the wrong response shape", () => {
  const networkData: unknown =
    JSON.parse('{"banana":true}')

  const result = GetQuestionsOutput(networkData)

  expect(result).toBeInstanceOf(type.errors)
})

The test does not merely inspect TypeScript diagnostics. It executes the validator that the SDK will later run against a real HTTP response.
